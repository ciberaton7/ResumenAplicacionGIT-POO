El Caos del Trabajo en Equipo

Imagina que te contratan en un equipo de 10 personas para crear el próximo RPG exitoso.

Todos abren el archivo Personaje.cs y empiezan a escribir sus ideas al mismo tiempo y se lo pasan por WhatsApp.

  • 🔥 Alguien borrará accidentalmente el código del otro.
  • 🔥 Habrá 10 versiones distintas del mismo archivo.
  • 🔥 ¡Nadie sabrá por qué el juego no compila!

La Solución de los Profesionales

Para evitar el caos, las empresas tecnológicas utilizan una fórmula de tres pasos:

  • Modularidad: Dividir el problema. Cada programador hace un archivo distinto.
  • POO (Contratos y Moldes): Reglas estrictas para que los archivos de todos encajen perfectamente. (Abstracción e Interfaces).
  • Control de Versiones (Git): La herramienta mágica que fusiona el trabajo de todo el equipo en la nube de forma segura.

1. Abstracción (El Molde Base)

Una Clase Abstracta es un plano incompleto. Define la identidad o genética principal, pero deja "huecos" intencionales.

  • Regla de Oro: ¡NO puedes usar new directamente en una clase abstracta!
  • Obliga a sus clases hijas a programar los métodos marcados como abstract.

Si tu clase hija no programa el método abstracto, Visual Studio marcará error rojo en toda la clase. ¡Es un molde obligatorio!

// 1. El padre (Molde base)
public abstract class SerMitologico
{
    public string Nombre { get; set; }
    
    // Método abstracto (Sin llaves, sin código)
    // Obliga al hijo a decir CÓMO ataca
    public abstract void Atacar(); 
}

// 2. El hijo (El objeto real)
public class Duende : SerMitologico
{
    // ¡El 'override' es obligatorio!
    public override void Atacar()
    {
        Console.WriteLine("El duende lanza una piedra");
    }
}

2. Interfaces (El Contrato)

Mientras la abstracción dice "qué eres", la interfaz dice "qué sabes hacer".

  • No tiene código, variables, ni lógica. Solo promesas.
  • En C#, solo puedes heredar de UNA clase padre, ¡pero puedes firmar MÚLTIPLES contratos (interfaces)!
  • Por convención profesional, siempre inician con la letra I.

¿Sabías que en una interfaz no se escribe la palabra public en sus métodos? ¡Todo dentro de una interfaz es público y abstracto por defecto!

// 1. Los Contratos
public interface IMagico
{
    void LanzarHechizo(); // Sin 'public'
}

public interface IVolador
{
    void Volar();
}

// 2. La clase firma los contratos múltiples
public class Supay : SerMitologico, IMagico, IVolador
{
    public override void Atacar() { ... }
    
    public void LanzarHechizo() { ... }
    public void Volar() { ... }
}

El Puente entre Nosotros: GIT

Ya sabemos hacer piezas modulares e independientes usando POO. ¿Cómo las unimos al proyecto del Docente (Líder Técnico)?

  1. Fork (Bifurcar): Haces una copia exacta de mi repositorio en tu cuenta de GitHub.
  2. Clone (Clonar): Descargas tu copia a Visual Studio.
  3. Commit & Push: Programas tu clase, guardas localmente y subes a tu nube.
  4. Pull Request (PR): Me envías una solicitud diciendo: "Profe, termine mi clase, únela al juego principal".

Guía del Estudiante (Paso a Paso)

  1. Entra al enlace de GitHub del docente y haz clic en Fork.
  2. Abre Visual Studio 2022 y haz clic en Clonar un Repositorio (pega la URL de tu Fork).
  3. En el proyecto, crea una nueva clase con el nombre de tu criatura (Ej. Sirena.cs).
  4. Haz que herede de SerMitologico y cumpla el override de Atacar().
  5. Haz que implemente la interfaz IRecompensable y programa el método SoltarBotin().
  6. Ve a "Cambios de Git", escribe qué hiciste, y haz clic en Confirmar todo e Insertar.
  7. Ve a tu GitHub y haz clic en Contribute -> Open Pull Request.
